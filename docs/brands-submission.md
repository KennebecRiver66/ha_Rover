# Brand images

Home Assistant shows a generic puzzle piece for any integration it has no artwork
for, which is the first thing a new user notices and the least fixable-looking.
This integration ships its own artwork, so that no longer happens:

```
custom_components/rover_client/brand/
├── icon.png            256x256
├── icon@2x.png         512x512
├── logo.png            409x128
├── logo@2x.png         816x256
├── dark_logo.png       409x128
└── dark_logo@2x.png    816x256
```

The files are generated by [`scripts/make_brand_assets.py`](../scripts/make_brand_assets.py).
Edit the script, re-run it and commit the result — don't retouch the PNGs by hand,
or the next run will quietly undo the retouching.

```bash
pip install pillow
python3 scripts/make_brand_assets.py
```

The mark is a speech bubble with a paw in it, because what the integration reads is
Rover **conversations**. It is deliberately not a copy of Rover's own logo: this is
a third-party client, and looking like the official thing would be both a trademark
problem and a lie about who wrote it. `home-assistant/brands` asks the same of
custom integrations.

## Who sees them

**Home Assistant 2026.3 and later** reads `brand/` straight out of the integration
directory, and local images take priority over the brands CDN — see the
[Brands Proxy API announcement](https://developers.home-assistant.io/blog/2026/02/24/brands-proxy-api).
Nothing else is needed, and the HACS brands check accepts this layout, which is why
`.github/workflows/validate.yml` no longer ignores that check.

**Home Assistant older than 2026.3** ignores `brand/` and asks the CDN, so those
installs still see a puzzle piece. Fixing that needs the images in
[`home-assistant/brands`](https://github.com/home-assistant/brands), which is a pull
request against someone else's repository and therefore cannot be done from here.

## Submitting to home-assistant/brands

Only worth doing while Home Assistant versions before 2026.3 are still worth
supporting — `hacs.json` currently declares a floor of 2025.2.0, so for now it is.

1. Fork and clone `home-assistant/brands`.
2. Copy the generated files in, keeping the names exactly:

   ```bash
   mkdir -p custom_integrations/rover_client
   cp /path/to/this/repo/custom_components/rover_client/brand/*.png \
      custom_integrations/rover_client/
   ```

3. Check them against the
   [image specification](https://github.com/home-assistant/brands#image-specification):
   PNG, transparent, trimmed of empty edges, icon exactly 256x256 (512x512 hDPI),
   logo shortest side 128 (256 hDPI). The generator already satisfies all of these,
   so a failure here means the script changed.
4. Open the PR with a title like `Add brand images for rover_client` and note in
   the description that the artwork is original, not Rover's logo.
5. When it merges, the CDN takes up to 24 hours (Cloudflare) and browsers up to 7
   days to catch up. Nothing needs changing in this repository afterwards.

The `custom_integrations` folder is documented upstream as legacy, so expect a
reviewer to ask whether local `brand/` images would do instead. For anyone on
2026.3+ they already do.
